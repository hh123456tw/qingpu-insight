# AI 物件分析價格摘要設計

## 背景

目前右側 AI 回覆卡已能顯示 Gemini／Rule 的證據式物件分析，也會將
`查看資料依據` 預設收合。不過主要價格結論仍混在純文字回覆中，使用者需要
自行找出開價、估價區間、差距與信心度；展開資料依據後看到的則是
`listing.price` 等內部 fact ID，不利於一般使用者理解。

此外，價格位置與百分比若只由 LLM 組織文字，可能出現比較基準不清楚或算術
不一致。這會直接傷害房價分析工具最重要的可信度。

## 目標

- 讓使用者在數秒內看懂開價相對於模型估價區間的位置。
- 所有價格差額與百分比由確定性程式計算，不交由 LLM 計算。
- 保留 Gemini 的白話分析，但將其定位為證據解讀而非數值來源。
- 將展開後的資料依據改為中文標籤與可讀值。
- 維持目前頁面、資料庫與對話流程，不擴大為整站重新設計。

## 非目標

- 不修改左側物件資料與估值區塊。
- 不改變 `查看資料依據` 預設收合的行為。
- 不加入圖表、推薦分數、投資報酬率或「值得買」判定。
- 不修改既有對話、訊息及證據資料表結構。
- 不重新訓練或發布估值模型。

## 核心設計

### 1. 確定性價格摘要

每則具有有效估值證據的助理訊息，在 AI 文字之前顯示價格摘要：

- `591 開價`
- `模型估價區間`
- `開價位置`
- `模型信心`

摘要由訊息所綁定的 `evidence_revision` 產生，不使用目前最新版本覆蓋歷史
訊息。使用者重新整理物件後，舊訊息仍顯示當時版本的摘要。

591 價格固定標註「開價，不代表成交價」。

### 2. 價格位置與百分比規則

令：

- `asking` 為 591 開價；
- `low` 為模型估價下限；
- `point` 為模型估值點；
- `high` 為模型估價上限。

規則如下：

1. 若 `low <= asking <= high`，顯示「落在模型估價區間內」，不顯示偏高或
   偏低百分比。
2. 若 `asking < low`：
   - 差額為 `low - asking`；
   - 百分比為 `(low - asking) / low * 100`；
   - 顯示「低於區間下限 X 萬（Y%）」。
3. 若 `asking > high`：
   - 差額為 `asking - high`；
   - 百分比為 `(asking - high) / high * 100`；
   - 顯示「高於區間上限 X 萬（Y%）」。
4. 百分比顯示一位小數，價格沿用全站的「萬」格式。
5. 與 `point` 的差距可保留為證據資料，但不作為卡片的主要價格位置。

### 3. 資料完整性保護

只有在以下條件成立時顯示完整價格摘要：

- `asking`、`low`、`point`、`high` 均為有限正數；
- `low <= point <= high`；
- 訊息的 `evidence_revision` 能找到對應證據包。

若估值點不在區間內，卡片顯示：

> 估值資料不一致，請重新估價。

此時不顯示價格位置或百分比，也不讓 Gemini 的數值敘述取代確定性摘要。

若只有部分價格欄位缺失，省略價格摘要，保留原本 AI 回覆與資料依據，避免
舊對話因新欄位要求而無法顯示。

### 4. AI 回覆責任

Gemini／Rule 繼續輸出 2～4 點精簡分析及一般建議，但：

- 不負責計算開價與估價區間的差額或百分比；
- 僅能引用證據包中存在的數字；
- 不使用「值得買」、「一定上漲」等決策式語句；
- 低信心或區間過寬時，應明確提示需要核對物件條件與同社區成交案例。

既有 citation 驗證維持不變。若供應商回覆未通過驗證，沿用目前的 Rule
fallback，不新增另一套錯誤流程。

## API 與資料流

### 訊息投影

`GET /api/conversations/<conversation_id>/messages` 在序列化助理訊息時，依
該訊息的 `evidence_revision` 取得對應證據包並投影：

```json
{
  "price_summary": {
    "asking_twd": 13500000,
    "low_twd": 14034000,
    "point_twd": 17546000,
    "high_twd": 21058000,
    "position": "below",
    "gap_twd": 534000,
    "gap_percent": 3.8,
    "confidence": "low",
    "confidence_reason": "估價區間較寬"
  },
  "citation_details": [
    {
      "id": "listing.price",
      "label": "591 開價",
      "value": "1,350 萬",
      "source": "591 物件頁"
    }
  ]
}
```

`position` 僅允許 `below`、`inside`、`above`、`inconsistent`。

後端應先收集本頁訊息中不重複的證據版本，再各讀取一次，避免逐訊息重複
查詢同一證據包。使用者訊息的 `price_summary` 為 `null`，不顯示分析卡。

### 相容性

- 現有訊息欄位不移除、不更名。
- 無對應證據包或舊證據缺欄位時，新增欄位回傳 `null` 或空陣列。
- 前端仍能渲染只有 `content` 與 `citations` 的舊 API 回應。
- 不新增資料庫 migration。

## 前端呈現

助理訊息的順序為：

1. 模型／證據版本標頭；
2. 價格摘要；
3. AI 分析文字；
4. 一般建議；
5. `查看資料依據（N）` 收合區；
6. provider fallback 提示。

價格摘要使用現有卡片色系，不引入新的設計系統。桌面版以三個簡潔欄位排列，
窄螢幕改為單欄。`inside` 使用中性綠色，`below` 使用資訊色，
`above`／`inconsistent` 使用警示色；不得只靠顏色表達狀態，文字必須完整。

資料依據展開後每筆顯示：

```text
591 開價
1,350 萬 · 591 物件頁
```

若 API 沒有 `citation_details`，退回顯示原始 citation ID，確保舊資料仍可
查看。

## 中文欄位名稱

至少支援以下映射：

| Fact ID | 顯示名稱 |
|---|---|
| `listing.price` | 591 開價 |
| `listing.unit_price` | 591 開價單價 |
| `listing.area` | 建物面積 |
| `valuation.point` | 模型估值 |
| `valuation.interval` | 模型估價區間 |
| `valuation.asking_gap_amount` | 開價與模型估值差額 |
| `valuation.asking_gap_percent` | 開價與模型估值差距 |
| `valuation.asking_position` | 開價位置 |
| `valuation.confidence` | 模型信心 |
| `market.sample_size` | 相似成交案例數 |
| `market.median_unit_price` | 附近成交單價中位數 |

未列出的 fact 使用證據本身的 `label`；只有 label 也缺失時才顯示 fact ID。

## 驗證重點

- 開價低於下限時，以估價下限為基準正確算出差額與百分比。
- 開價高於上限時，以估價上限為基準正確算出差額與百分比。
- 開價在區間內時不產生誤導性的高低百分比。
- `low > point`、`point > high`、零值、非數字及缺欄位安全降級。
- 每則歷史訊息使用自身證據版本，不誤用最新估值。
- citation 顯示中文 label、value 與 source，且資料依據預設保持收合。
- 舊訊息與缺失新欄位的 API 回應仍可正常顯示。
- 鍵盤可操作 `details/summary`，狀態不只依靠顏色。

## 成功標準

1. 使用者不展開資料依據，也能直接讀懂開價與模型區間的關係。
2. 畫面中所有差額與百分比都能由相同輸入確定重算。
3. Gemini 更換模型或調整措辭不會破壞價格摘要。
4. 展開資料依據後不再以內部 fact ID 作為主要顯示文字。
5. 現有對話、fallback、重新整理及歷史訊息功能不退化。
