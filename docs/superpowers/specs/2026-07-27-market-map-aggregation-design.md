# 成交地圖完整資料聚合設計

日期：2026-07-27

## 問題與目標

首頁「成交筆數」來自完整篩選結果，但成交地圖與「近期成交」共用
`/api/transactions`，因此地圖實際只畫最新 20 筆。這會讓使用者誤以為
一萬多筆資料只有少量座標。

本次目標是讓地圖代表目前篩選條件下的全部有效座標資料，同時維持瀏覽器
效能與畫面可讀性。「近期成交」改為顯示最新 100 筆，方便人工瀏覽。

## 範圍

### 包含

- 新增獨立的成交地圖 API。
- 使用與市場摘要相同的交易類型、生活圈、日期、坪數、建物類型與房數篩選。
- 後端依地圖縮放層級與可視範圍聚合座標。
- 前端在初次載入、篩選變更及地圖停止移動後更新群組。
- 顯示符合條件筆數、有效座標筆數、未定位筆數與目前群組數。
- 群組彈窗顯示成交筆數、中位單價及最近成交日期。

### 不包含

- 不導入 PostGIS、向量圖磚或外部付費地圖服務。
- 不改變模型訓練資料或估價流程。
- 不在瀏覽器一次建立一萬多個 Leaflet marker。
- 不精確顯示遭來源資料模糊化的門牌位置。

## API 設計

新增：

`GET /api/market/map-points`

沿用 `MarketFilters` 的查詢參數，另接受：

- `zoom`：Leaflet 縮放層級，允許 10 至 19。
- `south`、`west`、`north`、`east`：可選的目前地圖邊界；四項必須一起提供。

回應：

```json
{
  "total_records": 16293,
  "located_records": 16120,
  "unlocated_records": 173,
  "group_count": 84,
  "items": [
    {
      "latitude": 25.0123,
      "longitude": 121.2145,
      "record_count": 37,
      "median_unit_price_per_ping_twd": 438000,
      "latest_transaction_date": "2026-06-12"
    }
  ]
}
```

`total_records` 是套用市場篩選後的全部筆數；地圖邊界只限制 `items`，
不改變這個總數。`located_records` 與 `unlocated_records` 讓座標品質可見。

無效縮放層級、缺少部分邊界或反向邊界回傳既有格式的 400 輸入錯誤。

## 聚合規則

1. 先套用既有 `filter_market`。
2. 計算完整篩選結果的總筆數及座標完整度。
3. 若提供地圖邊界，再限制要聚合的有效座標資料。
4. 依 `zoom` 選擇固定經緯度網格大小；縮放越近，網格越細。
5. 每格回傳座標平均值、筆數、單價中位數與最近交易日期。
6. 若目前可視範圍仍超過 500 個群組，逐步放大網格，直到不超過 500。
7. 空結果回傳計數與空陣列，不視為錯誤。

這個策略能讓放大地圖時群組逐步拆開，也能把每次傳輸與 Leaflet 圖層控制在
合理大小。相同或高度模糊化的來源座標仍可能維持同一群組。

## 前端流程

地圖與近期成交使用不同請求：

- `/api/transactions?limit=100`：固定取得最新 100 筆，供表格使用。
- `/api/market/map-points`：供地圖使用。

地圖上方加入簡短狀態：

`符合 16,293 筆｜有座標 16,120 筆｜目前顯示 84 個群組`

群組以圓形 marker 表示，筆數較多時半徑略增，但設上限避免遮住整張地圖。
彈窗不顯示內部欄位或完整地址。篩選改變時重新取得摘要、趨勢、近期成交與
地圖資料；單純縮放或拖曳時只重新取得地圖資料。

地圖請求使用獨立 `AbortController` 與短暫 debounce，避免快速移動造成舊回應
覆蓋新畫面。請求失敗時保留原有群組並顯示「地圖資料載入失敗」，其他首頁
區塊仍可使用。

## 測試與驗收

採 TDD 實作，測試先失敗再加入正式程式：

- 單元測試：完整資料會被聚合，計數正確，缺少座標不進入群組。
- 單元測試：縮放提高會產生較細群組，群組上限不超過 500。
- API 測試：市場篩選與邊界正確傳遞，錯誤參數回傳 400。
- 前端契約測試：地圖請求包含篩選、縮放與邊界，近期成交明確要求 100 筆。
- 瀏覽器驗收：首頁顯示完整筆數與群組數；縮放後群組會更新；近期成交仍為
  最新 100 筆；其他摘要與篩選功能不退步。

完成標準：預設中古屋畫面不再以約 20 個點暗示完整資料量，且地圖狀態中的
`total_records` 與市場摘要的 `record_count` 相同。
