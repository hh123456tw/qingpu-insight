# Qingpu Insight AutoML-lite 設計規格

**日期：** 2026-07-28  
**狀態：** 已完成互動設計，等待書面規格核准  
**範圍：** 管理中心的受控式自動調參、排行榜、停止操作與候選模型治理

## 1. 目標

在既有「導引式調參」旁新增「自動探索」模式，讓使用者不需輸入模型參數，
只需選擇市場與時間預算，即可由 Optuna 搜尋現有模型的合理參數組合。

AutoML-lite 必須沿用現有的資料切分、模型評估、年度回測、分站檢查、
車位一致性與人工發布流程。它只能產生候選模型，不能自動發布或取代正式模型。

本功能同時服務兩個目的：

1. 期中專題：用簡單操作展示模型訓練、比較與治理流程。
2. 求職作品：說明如何在有限運算預算下導入自動調參，同時避免只追求單一分數。

## 2. 非目標

- 不導入 FLAML、AutoGluon 或 XGBoost。
- 不建立第二套模型 artifact 或發布格式。
- 不建立 AutoML 專用資料庫。
- 不自動發布排名第一的模型。
- 不支援暫停後續跑。
- 不支援使用者直接編輯 Optuna 搜尋空間。
- 不為了 AutoML 重寫既有模型訓練、報告或發布架構。

## 3. 使用者操作

管理中心的「訓練候選模型」保留既有導引式調參，新增以下控制：

- 訓練方式：
  - `導引式調參`
  - `自動探索`
- 市場：
  - 中古屋
  - 預售屋
  - 可個別勾選，進入自動探索時預設只選中古屋
- 搜尋預算：
  - 快速探索：5 分鐘
  - 標準探索：15 分鐘
  - 深入探索：30 分鐘
- 動作：
  - `開始自動探索`
  - 執行期間顯示 `停止探索`

自動探索模式不顯示原本的自訂模型參數欄位。使用者只需理解市場與時間預算。

## 4. 架構

新增獨立的 `automl_search.py`，其責任僅限於：

- 接收市場、資料切分、時間預算與停止訊號。
- 使用 Optuna 提出受限制的模型參數。
- 呼叫既有模型建立與評估函式。
- 保存每個 trial 的狀態、參數、指標、耗時與失敗原因。
- 依既有 calibration 門檻建立排行榜並回傳前三名。

它不得：

- 寫入正式模型目錄。
- 啟用或回滾模型。
- 自行定義另一套資料切分。
- 繞過模型訓練服務的 artifact 驗證。
- 直接操作資料庫或 Flask request。

既有 `ModelTrainingService` 負責編排完整流程：

1. 建立背景工作。
2. 載入與驗證資料。
3. 依市場執行 AutoML 搜尋。
4. 對前三名不同參數候選執行正式 holdout 與年度回測。
5. 選出第一個通過完整發布門檻的候選。
6. 建立既有 schema 的 candidate artifact、模型報告與 manifest。
7. 等待使用者透過既有 preview／confirm 發布流程處理。

## 5. 搜尋模型與參數

Ridge 保持固定設定，只作為 baseline，不由 Optuna 調參。

Optuna trial 在 Random Forest 與 HistGradientBoosting 之間選擇一種模型，
再提出該模型的參數。

### 5.1 HistGradientBoosting

| 參數 | 範圍 |
|---|---|
| `learning_rate` | 0.02–0.12，log scale |
| `max_iter` | 150–800 |
| `max_leaf_nodes` | 15–63 |
| `l2_regularization` | 0.1–10，log scale |

### 5.2 Random Forest

| 參數 | 範圍 |
|---|---|
| `n_estimators` | 150–800 |
| `min_samples_leaf` | 2–12 |
| `max_features` | 0.5–1.0 |

### 5.3 中古屋近期權重

中古屋 trial 同時從以下值選擇近期權重半衰期：

`24、36、48、60、72` 個月。

預售屋不使用近期權重半衰期搜尋。

所有 study 使用固定 seed `42` 的 Optuna sampler，且 trials 依序執行，
不做平行搜尋。相同程式版本、資料快照、市場與預算設定必須可重建相同的
試驗順序；實際耗時造成的完成 trial 數可以不同。

## 6. 時間預算與 trial 上限

| 模式 | 搜尋時間 | Trial 上限 |
|---|---:|---:|
| 快速探索 | 5 分鐘 | 12 |
| 標準探索 | 15 分鐘 | 35 |
| 深入探索 | 30 分鐘 | 70 |

搜尋在先達到時間或 trial 上限時結束。時間預算只涵蓋 Optuna 搜尋階段；
前三名的正式 holdout、年度回測、報告與 artifact 建立不計入搜尋時間。

前端在搜尋結束後改顯示「搜尋完成，正在驗證前三名」，避免讓使用者誤以為工作卡住。

## 7. 排名與候選選擇

每個 trial 使用既有 calibration 時間切分評估。

排名規則：

1. 通過既有 calibration 整體改善與分站退步限制的 trial 排在前面。
2. 合格 trial 依整體 MAE 由低到高排序。
3. 不合格 trial 保留在排行榜，並顯示未通過原因。
4. 相同分數時依 trial 編號排序，確保穩定輸出。

搜尋結束後，取最多三名「參數不同」的合格 trial 執行正式驗證；若合格 trial
少於三名，就只驗證實際存在的合格 trial。正式驗證沿用現有：

- Final holdout 指標。
- A17／A18／A19 分站指標。
- 年度 release backtests。
- 資料覆蓋率與新鮮度檢查。
- 車位價格一致性檢查。
- 既有 artifact smoke test。

前三名中第一個通過所有發布檢查的模型成為本次候選。若三名皆失敗：

- 工作仍可正常完成。
- 保存完整排行榜與正式驗證結果。
- 顯示「本次沒有可發布候選」。
- 不顯示發布按鈕。

排行榜第一名與可發布候選必須分開呈現。

## 8. 進度與結果呈現

### 8.1 執行中

前端顯示：

- 目前市場。
- 目前模型。
- 已完成 trial 數。
- 搜尋時間上限。
- 已耗時。
- 目前最佳 MAE。
- 目前最佳參數的精簡摘要。
- 最近一次 trial 的通過、未通過或失敗狀態。

介面不顯示不可靠的完成百分比，因為每個模型所需時間不同。

### 8.2 完成後

預設顯示前 10 名：

| 排名 | 模型 | MAE | MAPE | A17 MAPE | A18 MAPE | A19 MAPE | 耗時 | 結果 |
|---|---|---:|---:|---:|---:|---:|---:|---|

每列可展開查看完整參數與淘汰原因。第 11 名以後放在「查看全部試驗」內，
避免管理介面出現過長表格。

結果摘要必須用兩個不同欄位表示：

- `搜尋排名`
- `發布資格`

發布資格只能由完整發布檢查決定。

## 9. 停止行為

停止採合作式取消：

1. 使用者按下 `停止探索`。
2. 後端記錄該 run 的停止要求。
3. 目前正在執行的 trial 完成。
4. 搜尋器不再開始下一個 trial。
5. 工作轉為既有 `skipped` 終止狀態，摘要顯示「已由使用者停止」。

停止後：

- 保留已完成 trial 的排行榜。
- 不執行前三名正式驗證。
- 不建立可發布候選。
- 不刪除既有紀錄。

第一版使用 process-local 的停止登錄表，不新增資料庫 schema。若網站程序重啟，
既有工作復原機制將執行中的工作標記為中斷失敗，不自動續跑。

## 10. 錯誤處理

- 單一 trial 的模型訓練失敗：
  - trial 標記為失敗。
  - 保存安全的錯誤代碼。
  - 繼續下一個 trial。
- 所有 trial 都失敗：
  - 工作標記失敗。
  - 不建立候選。
- 資料驗證失敗：
  - 搜尋不啟動。
  - 沿用既有欄位化錯誤回應。
- 正式驗證未通過：
  - 工作成功完成。
  - 顯示沒有可發布候選及具體門檻原因。
- Artifact 或 manifest 寫入失敗：
  - 工作失敗。
  - 不留下可被發布流程讀取的半成品。
- 未知例外：
  - 沿用現有安全錯誤訊息，不在前端顯示路徑、secret 或 traceback。

## 11. 保存格式

不新增 AutoML 專用資料表。搜尋中的工作檔案先原子寫入
`outputs/automl/<run_id>/`。成功完成正式驗證時，完整 trial JSON 才複製到
既有 `candidates/<run_id>/`，並由候選 manifest 記錄相對路徑與 SHA-256。

若使用者停止搜尋，`outputs/automl/<run_id>/` 保留已完成排行榜，
但不建立候選 manifest 或模型 artifact，因此不會被發布服務辨識為候選。

既有候選 manifest 新增向後相容的 AutoML metadata：

- 模式與 schema version。
- 市場。
- 預算名稱與秒數。
- trial 上限、完成數、失敗數。
- seed。
- 是否由使用者停止。
- 排行榜前 10 名摘要。
- 完整 trial 結果檔案的相對路徑與 SHA-256。
- 進入正式驗證的 trial 編號。
- 最終候選 trial 編號；沒有候選時為 `null`。

成功完成的完整 trials 寫入候選目錄的 JSON 檔案，不放入資料庫。所有數值在
序列化前轉為 Python `int`／`float`，避免 NumPy scalar 造成 JSON 錯誤。

既有 schema-v3 artifact 欄位保持可讀；AutoML 欄位皆為 optional，使舊候選與
正式模型不受影響。

## 12. HTTP 與安全

沿用管理中心的 loopback、Host 與 CSRF 保護。

訓練建立 API 接受兩種互斥模式：

- 既有 `preset_comparison`
- 新增 `automl`

AutoML payload 只允許：

- 市場清單。
- 預算代碼：`quick`、`standard`、`deep`。

使用者不能從 HTTP payload 傳入 arbitrary estimator 名稱、Python expression、
檔案路徑或自訂搜尋範圍。

新增停止 endpoint，僅能停止：

- 存在的 `model_training` 工作。
- 目前為 active 狀態的 AutoML 工作。
- 當前程序持有停止控制器的工作。

重複停止必須具備冪等性，不得影響其他工作。

## 13. 依賴與相容性

- 新增 `optuna>=4,<5`。
- Python 版本維持 `>=3.11`。
- 不加入 FLAML、AutoGluon、XGBoost 或外部追蹤服務。
- Windows PowerShell、本機 Flask、MySQL 與現有 job executor 行為保持不變。
- 現有導引式調參、候選報告、模型觀測台與人工發布流程保持可用。

## 14. TDD 與驗收

實作必須使用 TDD，至少涵蓋：

- 預算與市場 payload 驗證。
- 搜尋空間邊界。
- 固定 seed 的試驗順序。
- calibration gate 優先的穩定排名。
- 單一 trial 失敗隔離。
- 合作式停止與重複停止。
- 前三名正式驗證與 fallback。
- 全部正式驗證失敗時不產生可發布候選。
- Manifest 與完整 trial JSON 的 schema、SHA-256 及 JSON-safe 數值。
- 既有導引式調參向後相容。
- 管理 API 的 loopback、Host 與 CSRF 保護。
- 前端 payload、進度、排行榜、展開與停止合約。
- AutoML 不會呼叫發布或改變正式模型指標。

完成時必須通過：

- 完整 pytest。
- Ruff。
- 所有 Node.js contract tests。
- `git diff --check`。
- 一次真實的 5 分鐘中古屋自動探索。

真實驗收必須確認：

1. 管理中心能建立 AutoML 工作。
2. 進度會持續更新。
3. 能產生排行榜與候選報告。
4. 發布閘門能正確決定是否可發布。
5. 正式模型指標在人工發布前完全不變。
