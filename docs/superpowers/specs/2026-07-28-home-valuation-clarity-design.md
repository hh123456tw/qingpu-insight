# 首頁、估價可信度與 AI 摘要精簡設計

**日期：** 2026-07-28
**狀態：** 已核准，待實作
**定位：** AIPE04 期中專題與求職 side project 的展示收斂

## 目標

本次調整不增加新的商業功能，而是改善既有首頁的理解成本：

1. 全站價格使用易讀的「萬」與「萬／坪」。
2. 修正相似成交分數的相對基準缺陷，讓信心度真正反映資料品質。
3. 讓 591 開價、模型估值、合理區間與實價登錄之間的關係一眼可懂。
4. 精簡 AI 摘要、歷史對話與近期成交，避免長文字與長表格淹沒主流程。
5. 用清楚的頁面順序呈現「市場資料 → 模型估價 → Evidence Pack → AI 解釋」。

## 非目標

- 不新增會員、收藏、付款、公開 SaaS 或雲端部署。
- 不新增 AutoML 或任意超參數搜尋。
- 不降低既有模型發布閘門。
- 不刪除報告後端、Evidence Pack、Provider、Benchmark、資料庫或歷史報告。
- 不改變 API 與資料庫保存價格時使用的 TWD 整數。
- 不把 591 開價混入實價登錄訓練標籤。

## 首頁資訊架構

首頁順序調整為：

1. 產品品牌與一句定位：`青埔智價 Qingpu Insight`
2. 591 單一物件分析入口
3. 市場篩選與市場分析結果
4. AI 條件估價
5. 方法與免責說明

`<h1>` 必須出現在第一個主要內容區，不能先以 591 表單的 `<h2>` 開場。

首頁移除整個「智慧購屋報告」表單及其前端 `/api/reports` 呼叫。591 對話助理成為首頁唯一的單一物件 AI 入口。後端報告 API、結構化報告、Provider、Benchmark、資料表與測試全部保留，供管理端、CLI 與作品集架構說明使用。

## 價格顯示契約

資料層與 API 繼續使用精確 TWD 整數；格式化只發生於 UI 與供 LLM 閱讀的 EvidenceFact 文字。

### 顯示規則

- 總價：`22,980,000 元` 顯示為 `2,298 萬`
- 非整萬總價：最多一位小數，例如 `15,377,250 元` 顯示為 `1,537.7 萬`
- 單價：`586,700 元／坪` 顯示為 `58.7 萬／坪`
- 零、缺值與非有限數字顯示為 `—`
- 千分位使用 `zh-TW`
- 不使用 `$`，避免讓使用者誤認為美元

### 使用範圍

- 市場 KPI
- 近期成交表格
- 地圖 popup
- AI 條件估價結果、合理區間、相似成交與影響因素
- 591 助理左側 Evidence Panel
- Rule／Ollama／Gemini 可見回答
- 新建立的 EvidenceFact
- 管理中心模型報告中的金額型指標；原始下載報告仍保留精確數值

JavaScript 使用一個共用、可測試的價格格式化模組；Python Evidence Builder 使用等價的格式化函式。舊對話若仍含 `1,234,567 元` 或 `123,456 元/坪`，前端只針對帶有明確貨幣單位的片段做相容轉換，不修改日期、距離或 fact ID。

## 相似成交與信心度

### 現有缺陷

現行相似度以「前五筆中最差案例的距離」正規化。因此每批最差案例的相似度固定接近 0，`0.60` 沒有跨查詢的一致含義；成交時間差又直接以月數加入距離，使多數物件難以取得 3 筆高相似案例。

### 新相似度

候選池與既有規則相同：

- 相同交易市場
- 最近 36 個月
- 優先同生活圈；同生活圈不足 3 筆時才擴大至 A17～A19
- 回傳最高 5 筆

每個維度先轉為 `0..1` 子分數，再計算加權平均：

| 維度 | 權重 | 子分數 |
|------|------|--------|
| 建物坪數 | 25% | `clip(1 - abs(diff) / 20, 0, 1)` |
| 捷運距離 | 20% | `clip(1 - abs(diff) / 1000, 0, 1)` |
| 房／廳／衛 | 15% | 三個 `clip(1 - abs(diff) / 2, 0, 1)` 的平均 |
| 屋齡 | 10% | `clip(1 - abs(diff) / 20, 0, 1)` |
| 樓層比例 | 10% | `clip(1 - abs(diff) / 0.5, 0, 1)` |
| 建物類型 | 10% | 相同為 1，不同為 0 |
| 成交新近度 | 10% | `clip(1 - months_old / 60, 0, 1)` |

若輸入或案例缺少某個可選維度，該維度不計分，剩餘權重重新正規化。不得把缺值當成 0 年屋齡或 0 樓層比例。

`similarity_score` 仍輸出 `0..1`，但改為具有固定尺度的絕對分數。相似度由高至低排序；排序相同時以交易日期較新者優先。

### 信心度規則

保留既有門檻：

- 無失敗條件：高
- 一項失敗條件：中
- 兩項以上：低
- 任一欄位超出完整訓練範圍：直接低
- 使用降級模型：直接低

失敗條件維持：

1. 輸入超出主要訓練範圍。
2. 估價區間寬度超過估值中心 30%。
3. 少於 3 筆相似度 ≥ 0.60 的成交案例。

591 開價高於模型估值或附近成交不屬於信心度扣分。信心度衡量的是模型與證據是否足夠，不是開價是否便宜。

所有可見信心度映射為：

- `high` → `高`
- `medium` → `中`
- `low` → `低`

API 仍保留英文 enum，避免破壞既有契約。

## 591 開價與估價解釋

Evidence Builder 在同時取得開價與估值時新增可引用的衍生事實：

- 開價與估值中心的金額差
- 開價與估值中心的百分比差
- 開價位於合理區間內、低於區間或高於區間

判讀文字不得只因 591 開價高於附近成交就說「不合理」。標準說法為：

> 591 顯示的是刊登開價，通常包含議價空間，不等同最終成交價。

範例：

- 開價：2,298 萬
- 模型估值：1,989 萬
- 開價高於估值中心約 15.5%
- 合理區間：1,538～2,441 萬
- 判讀：仍在合理區間內，但位於估值中心以上

## 估價價格位置圖

AI 條件估價與 591 助理的估價區塊使用同一個可存取的價格位置元件：

- 水平範圍左右端為估價下限與上限。
- 中心標記顯示模型估值。
- 有 591 開價時顯示第二個標記。
- 開價超出區間時，標記停在對應邊界並顯示「低於區間」或「高於區間」。
- 元件下方仍保留文字版數字與判讀，供窄螢幕與輔助技術使用。
- 不使用動畫作為唯一資訊來源。

## AI 摘要與引用

### 初始 Rule 摘要

初始摘要只顯示最多 6 個重點：

1. 開價
2. 模型估值
3. 開價與估值中心差距
4. 合理區間
5. 開價所處區間
6. 信心度與第一個主要原因

若缺少開價或估值，省略對應項目，不用低價值的成交細節填滿 6 項。一般建議最多保留一行。

### 後續 AI 回答

Provider prompt 要求回答以 3～4 個重點為主。Pydantic 的 30 claims 上限仍作為安全上限，不降低資料契約相容性。

後端仍必須：

- 驗證所有 property claim 的 fact ID
- 拒絕未知、空白或重複引用
- 將 citations 以獨立欄位保存

新回答的可見文字不再內嵌 `（依據：fact.id）`。前端顯示收合的「查看資料依據（N）」；展開後才列出 fact ID。舊回答中的 inline citation 在 render 時移除，但 citations 陣列仍可展開查看。

## 歷史對話

首頁不再橫向列出長連結。改為：

- 膠囊按鈕：`最近對話 N`
- 預設收合
- 點擊展開最多 5 筆
- 每筆顯示截短標題與台北時間
- 點擊項目恢復對話
- 再次點擊、點擊外部或按 Escape 收合
- 使用 `aria-expanded`、`aria-controls` 與鍵盤焦點管理
- 手機版選單使用容器滿寬，不超出 viewport

## 市場篩選與結果的視覺關係

市場篩選本身保持原位置與欄位。KPI、成交地圖、價格與交易量趨勢、近期成交共同包在一個「市場分析結果」容器中。

容器頂部顯示黏性條件列，例如：

`目前查看｜中古屋｜A17～A19｜全部坪數｜修改篩選`

- 條件列由目前的 URLSearchParams／表單狀態生成，不建立第二套篩選狀態。
- 捲動市場結果時條件列黏在 viewport 上方。
- 「修改篩選」將焦點與畫面移回市場篩選區。
- KPI、地圖、趨勢與近期成交不各自重複條件文字。
- 地圖與趨勢維持現有左右排列；窄螢幕維持單欄。

## 近期成交

- API 仍依共用市場篩選載入最近 100 筆。
- 首頁預設只 render 前 8 筆。
- 按鈕顯示 `顯示更多成交（100）`；展開後 render 全部已載入資料。
- 展開後按鈕改為 `收合近期成交`，收合回前 8 筆。
- 展開與收合不得重新呼叫 API。
- 新一輪市場篩選結果載入後回到收合狀態。
- 無資料時顯示目前條件下沒有成交，不顯示空表格。

## AI 條件估價表單

欄位不刪除，改用兩個有 legend 的視覺群組：

- 基本條件：市場、生活圈、坪數、建物類型、房數、屋齡、目前開價
- 詳細條件：捷運距離、廳數、衛數、所在樓層、總樓層、車位類型、車位面積

兩組預設都可見，避免把尚未填寫的 required 欄位藏在收合區。錯誤訊息應落在對應群組，並將焦點移至第一個錯誤欄位。

## 錯誤與載入狀態

- 價格格式化遇到無效值時顯示 `—`，不得拋出前端例外。
- 相似案例不足時保留「案例不足」原因，不捏造相似度。
- 市場任一 API 失敗時，條件列仍顯示目前條件；成功模組不被清空。
- 歷史對話載入失敗時只隱藏／停用歷史選單，不阻止建立新分析。
- 舊訊息的相容顯示不得修改資料庫原文。

## 測試與驗證

### Python

- 價格「萬」格式化的整萬、非整萬、零與缺值。
- 相似度每個維度的邊界、缺值權重重算與排序。
- 相似度不再依賴同批最差案例。
- 典型青埔物件可以取得合理數量的 ≥ 0.60 案例。
- 主要範圍外、完整範圍外、寬區間與降級模型仍正確判定信心度。
- 開價差額、百分比與區間位置 EvidenceFact。
- Rule 初始摘要最多 6 個重點，優先保留估價結論。
- 報告後端與 API 在首頁表單移除後仍通過既有測試。

### JavaScript

- 共用價格格式化契約。
- 歷史對話下拉的展開、外部點擊、Escape 與標題截短。
- 近期成交預設 8 筆、展開 100 筆、收合與新篩選後重置。
- 黏性條件列文字反映表單狀態，修改篩選可正確聚焦。
- 舊 citation 與舊價格文字的顯示相容。
- 價格位置圖在區間內、區間外與無開價情況。

### 瀏覽器驗證

1. 首頁 H1 與功能順序正確。
2. 市場篩選會同步更新 KPI、地圖、趨勢、近期成交與黏性條件列。
3. 捲到近期成交時仍能看見目前篩選摘要。
4. 歷史對話不再形成長連結列。
5. AI 條件估價與真實 591 分析都使用萬制價格與價格位置圖。
6. Gemini 回答精簡、fact ID 預設收合、信心度中文化。
7. 桌面與窄螢幕皆無水平溢出。

## 完成條件

- 首頁不再顯示智慧購屋報告表單。
- 首頁不存在 `$12,345,678` 或裸露的 `low/medium/high`。
- 典型物件不會因相對正規化缺陷而普遍得到低信心。
- 真正寬區間、資料不足、範圍外或降級模型仍明確顯示低信心及原因。
- 首頁預設高度明顯縮短，歷史對話與 100 筆近期成交均按需展開。
- 使用者可以從首頁順序說明專案的資料、模型與 AI 證據流程。
