# 青埔中古屋專注版設計

## 1. 背景

目前市場資料依內政部來源檔名區分：

- `h_lvr_land_a.csv` 視為中古屋；
- `h_lvr_land_b.csv` 視為預售屋。

但 A 表包含大量交易日早於完工日的預售契約、首次移轉或分件登記案件。
現有清洗規則沒有排除這些紀錄，導致：

- 2024-09 中古屋月中位數被拉低至約 18.6 萬／坪；
- 排除未完工移轉後，同月中位數約為 43.4 萬／坪；
- 15,931 筆中古屋訓練資料中有 10,648 筆負屋齡資料；
- 中古屋趨勢、比較案例與估價模型都受到污染。

現有預售屋正式模型也不適合作為展示主力：

- R² 約 0.142；
- MAE 約 8.37 萬／坪；
- MAPE 約 15.83%；
- 測試集 153 筆；
- 模型資料只到 2024-12-06。

本專案是期中專題與求職展示，因此產品主軸收斂為青埔中古住宅市場分析與估價。

## 2. 目標

1. 公開產品只展示與評估中古屋。
2. 排除不符合中古屋語意的未完工移轉資料。
3. 保留預售屋原始資料、artifact 與底層程式，避免不可逆刪除。
4. 重新建立乾淨資料並訓練一個可審查的中古屋候選模型。
5. 讓資料排除原因、樣本變化與模型結果可供專題報告和求職說明。

## 3. 非目標

- 不刪除預售屋資料庫紀錄、parquet 原始來源或既有模型 artifact。
- 不把 A 表的未完工移轉自動改標成預售屋，避免與 B 表重複。
- 不重新設計整套管理中心。
- 不自動發布重新訓練的中古屋模型。
- 不硬編碼水源南路、航空城安置住宅或特定建案黑名單。

## 4. 產品範圍

### 4.1 首頁

- 市場分析固定使用 `resale`。
- 移除中古屋／預售屋切換控制。
- AI 條件估價固定使用 `resale`。
- 移除估價表單中的市場選擇。
- 趨勢圖只顯示每月有效樣本至少 10 筆的月份。
- 近期成交與成交地圖沿用相同的中古屋篩選結果。

### 4.2 591 助理

- 公開入口只接受 `sale.591.com.tw` 中古屋詳細頁。
- `newhouse.591.com.tw` 不再出現在支援說明與首頁連結。
- 新建案 parser、資料表與底層程式保留，但公開流程不呼叫。
- 已存在的歷史預售屋對話保留可讀，不刪除。

### 4.3 管理中心與模型觀測台

- 一鍵 591 更新只執行 `sale`。
- Guided training 與 AutoML 只建立 `resale` 候選。
- 模型候選、正式模型、發布與回滾操作只顯示 `resale`。
- 現有預售屋正式模型仍保留在 artifact store，但不載入、不顯示、不發布。
- 模型報告必須顯示清洗前後筆數及 `future_completion_transfer` 排除數。

### 4.4 API

- 新增估價只接受 `transaction_type=resale`；缺省時使用 `resale`。
- 明確傳入 `presale` 時回傳穩定的 400 錯誤，不靜默改成中古屋。
- 市場公開 API 固定或限制為 `resale`，避免前端繞過 UI 查詢預售屋。
- 內部 parser 與儲存層仍可辨識既有 `presale` 紀錄，以維持歷史相容性。

## 5. 中古屋資料契約

一筆資料只有在既有條件全部成立，且符合以下規則時，才可進入中古屋分析：

```text
transaction_type == "resale"
completion_date is known
completion_date <= transaction_date
building_age_years >= 0
```

若 `completion_date > transaction_date`，排除原因為：

```text
future_completion_transfer
```

若中古屋 `completion_date` 缺失，排除原因為：

```text
missing_completion_date
```

原始資料不刪除。`analysis_eligible` 設為 false，品質報告記錄各排除原因。

備註含「預售屋、或土地及建物分件登記案件」只作診斷資訊，不單獨作為排除條件。
真正的排除依據是可驗證的完工日與交易日順序。

## 6. 資料與模型流程

```text
官方 A/B 表
  -> 正規化原始資料
  -> 中古屋語意清洗
  -> 保留排除統計
  -> market_transactions.parquet
  -> 中古屋時間切割
  -> calibration 選擇
  -> final test 一次性評估
  -> 產生候選 artifact 與模型報告
  -> 人工確認後才可發布
```

預售屋 B 表仍可下載與保存，但不進入公開分析、估價或模型訓練。

## 7. 相容性與失敗處理

- 舊預售屋 artifact 不刪除，避免歷史 manifest 失效。
- 讀取既有預售屋估價紀錄時仍能顯示已保存結果。
- 新的預售屋估價請求回傳 `presale_valuation_disabled`。
- 若清洗後中古屋任一 train/calibration/test 區段不足 100 筆，訓練必須失敗關閉並顯示安全訊息。
- 若重新訓練失敗，既有正式中古屋模型保持不變。
- 趨勢月份少於 10 筆時不回傳價格點，前端不以 0 補值或連線。

## 8. 驗證

### 8.1 資料

- 2024-09 的未完工移轉資料被排除。
- 2024-09 中古屋月中位數回到約 43.4 萬／坪。
- 中古屋模型資料沒有負屋齡。
- 品質報告包含 `future_completion_transfer` 與 `missing_completion_date`。
- A17、A18、A19 與各時間切割仍有足夠樣本。

### 8.2 產品

- 首頁沒有預售屋市場或估價選項。
- 591 助理首頁只宣告支援中古屋網址。
- 管理中心只啟動中古屋訓練與 `sale` 爬蟲。
- 模型觀測台只顯示中古屋候選與正式模型。
- 直接提交預售屋估價會得到明確 400 錯誤。
- 歷史預售屋報告與對話仍可讀取。

### 8.3 模型

- 重新訓練只建立中古屋候選，不自動發布。
- 報告列出清洗後樣本、時間切割、MAE、MAPE、RMSE、R² 與分站結果。
- 候選未通過既有 release gate 時仍可保存供研究，但不得標示建議發布。

## 9. 專題與求職敘事

本次調整可說明為：

> 初版依官方檔案類型區分中古屋與預售屋，但在趨勢圖發現異常低點後，追查到 A 表包含交易日早於完工日的預售契約與首次移轉資料。後續以可驗證的時間語意建立排除規則，保留原始資料與品質報告，並將產品收斂為中古屋估價，避免以低品質預售模型增加展示複雜度。
