# 中古屋公設比與建案特徵設計

日期：2026-07-29

狀態：設計已由使用者逐段核准，等待書面 spec 最終審閱

## 1. 目標

在不把期中專題與求職 side project 過度複雜化的前提下，研究並導入兩組同時能由實價登錄訓練、也能在 591 詳細頁估價時取得的中古屋特徵：

1. 公設比。
2. 時間安全的建案／社區歷史特徵。

新特徵必須經相同資料切割下的消融實驗證明有效，不能因為直覺合理就直接加入正式模型。缺少公設比或無法辨識建案時，現有估價流程仍須可用。

## 2. 不在本次範圍

- 不修改預售屋正式模型。
- 不以房屋朝向、裝潢程度或景觀作為正式 ML 特徵。
- 不把原始建案名稱或建商名稱直接 one-hot。
- 不讓 LLM 自動寫入建案主檔或決定模型用的建案 ID。
- 不大量爬取 591 建立建案資料庫；591 僅解析使用者提交的詳細頁。
- 不因本次訓練結果自動發布正式模型。

## 3. 研究依據

### 3.1 實價登錄欄位

專案現有官方 CSV 已包含：

- 主建物面積
- 附屬建物面積
- 建物移轉總面積
- 車位移轉面積
- 有無管理組織
- 有無電梯
- 主要建材
- 建物現況格局－隔間

目前 15,931 筆可用中古屋中，主建物、附屬建物、建物總面積及車位面積可支援接近 100% 的公設比推算。

其他候選欄位的區分能力有限：

- 主要建材幾乎都是鋼筋混凝土。
- 有無隔間幾乎都是「有」。
- 有無電梯幾乎都是「有」，且已被建物類型高度涵蓋。
- 有無管理組織資料完整，但絕大多數為「有」，只適合作為對照實驗。

### 3.2 591 詳細頁欄位

591 中古屋詳細頁有結構化「公設比」，並通常提供社區名稱。現有專案已解析 `community_name`，但尚未解析公設比。

建商名稱在 591 中古屋常存在於自由文案，格式與可信度不一致，因此不能直接作為模型輸入。建商只作為建案主檔的中繼資料與未來回退研究欄位。

參考來源：

- 內政部實價登錄資料說明：https://lvr.land.moi.gov.tw/R11/jsp/qa.jsp
- 國土資訊系統資料標準與 CSV 範例：https://ws.moi.gov.tw/001/Upload/400/relfile/9009/330578/df476d04-9525-4f90-abdf-68e951fb4364.pdf

## 4. 公設比資料契約

### 4.1 訓練資料

新增並保存原始面積欄位：

- `main_building_area_sqm`
- `auxiliary_building_area_sqm`

以不含車位的建物面積為分母：

```text
dwelling_area_sqm = building_area_sqm - parking_area_sqm
common_area_ratio =
  1 - (main_building_area_sqm + auxiliary_building_area_sqm)
      / dwelling_area_sqm
```

規則：

- 分母必須大於 0。
- 合理值域為 0 至 0.70。
- 無法推算或超出值域時保存為缺值，不刪除整筆交易。
- 模型只使用 `common_area_ratio`，不再同時加入與其互補的室內使用率。
- 報告保存有效覆蓋率、缺值率、中位數及分位數。

### 4.2 591 與手動估價

- 591 優先讀取房屋資料中的結構化「公設比」。
- 若結構化欄位缺少，但頁面有可信的主建物、附屬建物、公設與車位面積明細，可以使用相同定義推算。
- 擷取值超出 0 至 70% 時忽略該欄位並產生資料警告，不讓整個物件分析失敗。
- 手動條件估價新增選填公設比，接受 0 至 70%。
- 前端以百分比顯示與輸入，送入 API 前轉成 0 至 0.70 的比例值。
- 未提供公設比時，模型由缺值處理與既有特徵完成估價。

## 5. 建案主檔

### 5.1 第一版範圍

先收錄青埔成交量最高或 591 常見的約 20 至 30 個建案。主檔使用版本控制，允許人工校正。

建議欄位：

```text
community_id
canonical_name
aliases
builder_name
station_code
completion_year
address_patterns
coordinate_bounds
source_notes
```

`community_id` 是穩定機器 ID。名稱、別名與建商名稱可以修正，但不得改變既有 ID 的語意。

### 5.2 資料來源

依可靠度使用：

1. 官方預售屋建案名稱與起造人。
2. 實價登錄地址、座標、生活圈及完工年份。
3. 人工確認的青埔建案名稱與常見別名。
4. 使用者提交的 591 詳細頁只用來解析該物件，不自動寫回主檔。

### 5.3 辨識順序

```text
標準名稱完全相符
→ 已確認別名完全相符
→ 地址／座標範圍加完工年份相符
→ 未辨識
```

規則：

- 別名必須唯一對應一個 `community_id`。
- 地址或座標規則同時命中多個建案時視為未辨識。
- 模糊文字相似度只能提供人工檢查提示，不能直接成為正式模型 ID。
- LLM 不能建立、覆寫或選擇正式 `community_id`。
- 未辨識建案須回退到現有生活圈與空間特徵。

## 6. 時間安全建案特徵

模型不使用原始建案名稱，而使用：

- `community_known`
- `community_prior_count_24m`
- `community_prior_median_twd_per_ping_24m`
- `community_premium_vs_station_24m`

每筆歷史交易的特徵只能使用該筆交易日期以前的資料：

- 訓練資料以 expanding／時間順序產生統計。
- Calibration 與 final test 只能讀取其切割日期以前的建案統計。
- Final test 交易不得參與自己的建案中位數或溢價。
- 三個數值統計均使用交易日前 24 個月；同一天的其他交易也不納入。
- 建案溢價定義為建案 24 個月中位單價除以同生活圈、同建物類型 24 個月中位單價後減 1。
- 591 開價不得進入成交統計。
- 建案歷史成交少於 5 筆時，不產生中位數或溢價，僅保留 `community_known` 與成交筆數。
- 所有統計保存計算截止日期與建案主檔版本。

建商名稱第一版不作正式特徵。若後續研究，僅能作為建案樣本不足時的時間安全回退統計，不能直接 one-hot。

## 7. API 與前端

### 7.1 API

估價請求新增選填欄位：

- `common_area_ratio`
- `community_id`

591 證據可以保留原始 `community_name`，但模型只能接收正規化且已驗證的 `community_id`。

驗證規則：

- `common_area_ratio` 接受 0 至 0.70。
- `community_id` 必須存在於目前建案主檔。
- 兩欄缺少時不得回傳欄位錯誤。

### 7.2 首頁手動估價

- 新增「公設比（選填）」。
- 新增「建案（選填）」可搜尋下拉選單。
- 建案選項依 A17／A18／A19 篩選。
- 不要求使用者填建商。
- 未填新欄位時維持現有估價能力。

### 7.3 591 對話助理

- 自動擷取公設比與社區名稱。
- 顯示建案是否已辨識及公設比證據來源。
- 未辨識時顯示「本次以生活圈與鄰近成交為主」。
- 建案樣本不足時不得宣稱已使用可靠的建案溢價。

## 8. 實驗矩陣

所有實驗使用相同資料切割、相同隨機種子與相同近期權重。Baseline、E1 至 E4
只在 train／calibration 區段比較並選出一個鎖定方案；不得用 final test 挑選特徵。
方案鎖定後，只有 Baseline 與該方案各執行一次相同的 final test，以保留真正的樣本外證據：

| 實驗 | 新增內容 |
| --- | --- |
| Baseline | 現行正式 v3 特徵 |
| E1 | Baseline + 公設比 |
| E2 | Baseline + 建案統計 |
| E3 | Baseline + 公設比 + 建案統計 |
| E4 | E3 + 有無管理組織，僅作對照 |

主要候選是 E1、E2、E3。E4 用來證明管理欄位是否提供額外價值，不預設會進入正式模型。

## 9. 驗收與發布門檻

鎖定方案要成為推薦候選，必須在一次性 final test 同時符合：

- Final-test MAE 相對 Baseline 至少改善 2%。
- 整體 MAPE 不退步。
- A17、A18、A19 任一站 MAPE 不得惡化超過 1 個百分點。
- 至少 2/3 年度回測通過。
- 預測區間覆蓋率維持既有合理範圍。
- 591 公設比解析成功率達 70% 以上。
- 已知建案的 591 辨識成功率達 80% 以上。
- 缺少公設比或建案時，估價與 591 分析仍能完成。

591 成功率以至少 20 筆人工標記的青埔中古屋詳細頁驗證樣本計算。不得為達門檻大量爬取 591；樣本使用使用者已提交、人工測試或獲准取得的頁面，測試程式只保存必要的去識別化欄位 fixture，不保存整頁內容。建案辨識率的分母只計算主檔已收錄且人工確認名稱的物件，並另行報告全樣本覆蓋率，避免用縮小分母美化結果。

訓練只建立候選，不自動發布。管理者須在模型觀測台查看完整報告後人工發布。

## 10. 模型報告與可觀測性

候選報告新增：

- Baseline、E1 至 E4 的 calibration MAE、MAPE、RMSE、R²。
- Baseline 與鎖定方案的一次性 final-test MAE、MAPE、RMSE、R²。
- A17、A18、A19 分站誤差。
- 已知建案與未知建案的分組誤差。
- 公設比有效覆蓋率與分布。
- 建案辨識覆蓋率、未辨識筆數與樣本數分布。
- 建案主檔版本與統計截止日期。
- 最後入選的特徵組合與原因。
- 未通過實驗的結果與限制。

管理頁只呈現建案名稱、生活圈及聚合統計，不公開完整門牌。

## 11. 錯誤與降級

- 591 公設比異常：忽略欄位、保存警告、繼續分析。
- 591 建案未辨識：回退生活圈與座標模型。
- 建案樣本少於 5 筆：不使用建案價格溢價。
- 主檔別名衝突：主檔驗證失敗，不開始訓練。
- 主檔版本與 artifact 不一致：模型載入時安全降級並說明原因。
- 舊 artifact：保持相容，不要求存在新欄位。

## 12. 測試策略

本計畫實作依使用者既定規則採 TDD：

- 官方欄位解析與公設比公式單元測試。
- 合理值域、缺值與含車位案例測試。
- 591 結構化公設比與回退解析測試。
- 建案主檔唯一性與別名衝突測試。
- 建案名稱、別名、地址與座標匹配測試。
- 時間安全統計測試，證明未讀取未來交易。
- 訓練消融實驗與 artifact 契約測試。
- API 缺值、非法公設比及未知建案測試。
- 首頁與管理頁 JavaScript contract 測試。
- 591 真實詳細頁流程與模型觀測台瀏覽器驗證。

## 13. 展示價值

期中報告與面試可說明：

> 先盤點實價登錄和 591 詳細頁能共同取得的欄位，排除高缺值、低變異或定義不一致的候選，再以公設比與時間安全建案溢價做消融實驗。建案統計只使用預測日期以前的成交，無法辨識時回退生活圈，因此同時兼顧模型改善、資料洩漏防護與產品可用性。
